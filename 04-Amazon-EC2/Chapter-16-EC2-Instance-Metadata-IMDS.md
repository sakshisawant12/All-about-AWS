# 📖 What is Instance Metadata?

**Instance Metadata** is information about an EC2 instance that AWS makes available from inside the instance.

It includes details such as:

- Instance ID
- Instance Type
- Availability Zone
- AMI ID
- Private IP Address
- Public IP Address
- Security Groups
- IAM Role Credentials (if attached)

Applications running inside the EC2 instance can retrieve this information without logging in to the AWS Console.

# 🌐 Metadata Endpoint

AWS provides a special **link-local IP address** that is accessible only from inside the EC2 instance.

```
http://169.254.169.254/
```

This IP address is not accessible from the public Internet.

# 🚀 Accessing Metadata

To retrieve metadata from inside the EC2 instance:

```bash
curl http://169.254.169.254/latest/meta-data/
```

Example output:

```
ami-id
hostname
instance-id
instance-type
local-ipv4
public-ipv4
security-groups
```

Retrieve the Instance ID:

```bash
curl http://169.254.169.254/latest/meta-data/instance-id
```

Retrieve the Instance Type:

```bash
curl http://169.254.169.254/latest/meta-data/instance-type
```

Retrieve the Availability Zone:

```bash
curl http://169.254.169.254/latest/meta-data/placement/availability-zone
```

# 👤 IAM Role Credentials

If an IAM Role is attached:

```
EC2

↓

IAM Role

↓

IMDS

↓

Temporary Credentials

↓

Application
```

Applications automatically receive temporary credentials through IMDS.

No Access Keys need to be stored.

---

# 📖 Metadata vs User Data

| Metadata | User Data |
|-----------|-----------|
| Information about the EC2 instance | Startup configuration script |
| Generated by AWS | Provided by the user |
| Read using IMDS | Runs during first boot (by default) |
| Can be queried anytime | Used mainly for bootstrapping |

---

# 🔒 What is IMDSv1?

IMDSv1 is the original version.

Applications access metadata directly.

```
Application

↓

169.254.169.254

↓

Metadata
```

Simple to use, but more vulnerable to certain attacks such as Server-Side Request Forgery (SSRF).

---

# 🛡️ What is IMDSv2?

IMDSv2 improves security by requiring a **session token** before metadata can be accessed.

Flow:

```
Application

↓

Request Token

↓

IMDS

↓

Session Token

↓

Request Metadata

↓

Metadata Returned
```

This additional step helps protect against SSRF attacks.

---

# 🔄 IMDSv2 Example

Get a session token:

```bash
TOKEN=$(curl -X PUT "http://169.254.169.254/latest/api/token" \
-H "X-aws-ec2-metadata-token-ttl-seconds: 21600")
```

Use the token:

```bash
curl -H "X-aws-ec2-metadata-token: $TOKEN" \
http://169.254.169.254/latest/meta-data/instance-id
```

# 🌍 Real-World Example

A web application running on EC2 uploads files to Amazon S3.

```
Application

↓

IMDS

↓

Temporary IAM Credentials

↓

```

No permanent Access Keys are stored in the application.

# ⭐ Advantages

- Secure access to instance information
- Automatic IAM Role credentials
- No hardcoded AWS credentials
- Supports automation
- Available only from inside the EC2 instance

---

# ⚠️ Common Mistakes

- Using IMDSv1 when IMDSv2 is supported.
- Storing AWS Access Keys instead of using IAM Roles.
- Confusing Metadata with User Data.
- Assuming the Metadata Service is publicly accessible.

---

# ⭐ Best Practices

- Prefer IMDSv2 over IMDSv1.
- Use IAM Roles instead of permanent Access Keys.
- Restrict applications to only the metadata they require.
- Disable IMDSv1 for production workloads where possible.
- Follow the principle of least privilege for IAM Roles.

# 🎤 Interview Questions

### 1. What is EC2 Instance Metadata?

It is information about an EC2 instance that AWS makes available from inside the instance.

---

### 2. What is the IP address of the Instance Metadata Service?

```
169.254.169.254
```

---

### 3. What is the difference between Metadata and User Data?

Metadata provides information about the instance, while User Data is a startup script used to configure the instance during its first boot.

---

### 4. Why is IMDSv2 more secure than IMDSv1?

IMDSv2 requires a session token before metadata can be accessed, helping protect against SSRF attacks.

---

### 5. Can applications retrieve IAM Role credentials using IMDS?

Yes.

Applications running on the EC2 instance can obtain temporary IAM Role credentials through IMDS.

---

### 6. Is the Metadata Service accessible from the Internet?

No.

The Metadata Service is accessible only from within the EC2 instance.

---

# 🎯 Chapter Summary

The EC2 Instance Metadata Service (IMDS) allows applications running on an EC2 instance to retrieve information about the instance and obtain temporary IAM Role credentials. AWS recommends using **IMDSv2** because it adds token-based authentication, improving protection against security threats such as SSRF. Combined with IAM Roles, IMDS enables secure, credential-free access to AWS services.
